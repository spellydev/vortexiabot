Message Content Intent

Why Vortexia requests access to message content, what it does with that access, and how the feature is limited.

Technical review based on Vortexia 5.1.1 source · Updated 18 November 2026

Important threshold update: Discord’s current guidance (effective 10 June 2026) uses a threshold of 10,000 unique users who can access an app across all servers—not 1,000 members in one server and not the former 100-server threshold. If the app has fewer than 10,000 such users, Discord says it can enable privileged intents in the Developer Portal without a review application. If the Developer Portal specifically shows an application/review prompt, follow that prompt and submit the requested review. Discord’s current announcement.

1. Why Vortexia needs Message Content

The reviewed Vortexia 5.1.1 code currently has GatewayIntentBits.MessageContent commented out in its client intent list. The MessageCreate handler and feature implementations are present, but ordinary guild message text is unavailable without the privileged intent. The requested access is for these concrete user-facing features:

  • Custom AutoMod: detect configured invite links, external links, excessive caps, emoji floods, wall-text, repeated messages and spam patterns; apply the server’s configured moderation response.
  • Custom auto-responses: match a message against a server administrator’s configured trigger and return the configured response.
  • Vortexia AI: respond when a member intentionally mentions the bot or replies to it; text (and an eligible image attachment, if supplied) is used as the prompt for the configured AI provider.
  • Button-started input: read a value a user deliberately submits after selecting a bot workflow, process it, and attempt to delete that submitted message.
  • Leveling anti-farming: when leveling is enabled, assess whether a message contains meaningful, non-repeated text before awarding XP.
  • Deleted/edited message recovery: temporarily cache the latest deleted or edited message in a channel for the snipe feature.

Slash commands, command options, ordinary server information, and most configuration panels do not require Message Content. The request is limited to the message-driven features above.

2. Data minimization and safeguards

  • The message handler ignores bot-authored messages and messages outside guilds.
  • AutoMod text matching, short spam/repetition windows, leveling anti-farming comparisons and snipe records operate in memory; these message-text buffers are not persisted to the bot’s JSON data files.
  • If a server administrator configures an AutoMod log channel, the bot may post up to 900 characters of a triggering message into that Discord channel for moderator review. That log is then retained/controlled by the server’s Discord channel settings and moderation practices.
  • AI is activated by an explicit bot mention or reply-to-bot interaction, not by silently sending every message to an AI service.
  • AI conversation context is held in process memory with a bounded context window and is cleared when the process restarts or sessions are evicted. Prompts are sent to the AI provider configured by the operator for inference.
  • The bot does not use Discord API message content to train its own machine-learning models.
  • Persistent records are feature-specific (for example warnings, invite attribution, AFK status, tickets, levels and server settings) and are described in the public Privacy Policy.
  • Access to the bot host and data directory should be restricted to trusted operators. Server administrators control which features are enabled.

3. What Vortexia does not use it for

  • No advertising, sale of message content, data brokerage or unrelated user profiling.
  • No bulk scraping or historical message archive scanning.
  • No training of Vortexia-owned AI/ML models using Discord API Data.
  • No use of content from servers where Vortexia is not installed.

4. Application response draft

Use this as a starting draft only. Keep it truthful, edit it to match the live production deployment and the exact questions shown in your Developer Portal.

Which privileged intent are you requesting?

Message Content Intent (MESSAGE_CONTENT).

Describe why your application needs this intent.

Vortexia is an all-in-one Discord community bot. Message Content is required for specific, opt-in message-driven features that cannot function correctly using message metadata alone: (1) custom AutoMod rules that inspect message text for configured spam, repeated content, invite links, external links, excessive caps, emoji floods, configured banned words, spoilers and long messages; (2) administrator-configured keyword/phrase auto-responses; (3) Vortexia AI, which responds only when a user intentionally mentions the bot or replies to it; and (4) a button-initiated input flow where a user deliberately submits text for a pending configuration action; (5) message-quality checks for enabled leveling anti-farming; and (6) temporary deleted/edited-message recovery (snipe) buffers. If a server administrator configures an AutoMod log channel, up to 900 characters of the triggering message may be posted there for moderator review. Slash commands and ordinary command handling do not rely on this intent. We request only the access needed for these features.

How do you use and store message content?

Message text is processed by the relevant feature in the MessageCreate handler. AutoMod uses short-lived in-memory windows to detect spam and repeated messages; auto-response matching compares the incoming text with triggers configured by that server’s administrators. The reviewed AutoMod/leveling/snipe text buffers are held in process memory and are not written to persistent JSON data files. If the server configures an AutoMod log channel, up to 900 characters of the triggering message may be included in a log message posted to that Discord channel. For AI, the prompt (and, when the user replies to someone else, up to 600 characters of that referenced message) is sent to the AI provider configured by the operator only after a user mentions or replies to the bot; bounded conversation context is held in process memory and is cleared on process restart/session eviction. Eligible image attachments may also be sent to the configured AI provider when the user invokes the AI interaction with an image. We do not use Discord API Data to train our own models.

How do you protect user data?

We limit content processing to the features described above, ignore bot-authored messages and non-guild messages in the guild message handler, avoid persistent storage of ordinary message text in the reviewed message-processing paths, and restrict persistent records to feature operation such as server configuration, warnings, invite tracking, AFK, tickets and leveling. Bot hosting and data-directory access should be limited to trusted operators. Our public Privacy Policy explains data categories, configured third-party providers, retention limitations and how users can request deletion.

Why can’t you use slash commands or metadata instead?

Slash commands are used wherever a user explicitly invokes a command, and they do not require Message Content. However, they cannot replace passive message-triggered moderation rules, configured keyword/phrase auto-responses, or the ability to understand the text of a message that deliberately mentions or replies to Vortexia AI. Message metadata alone does not contain the text needed to identify links, repeated phrases, excessive caps, configured trigger phrases or the user’s AI prompt. These specific features therefore require MESSAGE_CONTENT.

5. Evidence to capture before submitting

  • Screen recording showing a test server with AutoMod enabled: demonstrate a harmless test phrase/link being detected and the configured action.
  • Screen recording showing an administrator configuring an auto-response and a member triggering that exact phrase.
  • Screen recording showing a member explicitly mentioning Vortexia AI and receiving a response; show that an ordinary unrelated message does not trigger AI.
  • Show the relevant settings panels and the public Privacy Policy URL.
  • Capture the Developer Portal’s actual app user count and the exact review prompt if one is displayed.
  • Do not stage fake production numbers or claim that a feature is live if it is not enabled in the submitted build.
Before submitting: make sure the Privacy Policy URL is publicly reachable, the bot’s production code matches these statements, the AI provider list is accurate, and your video demonstrates real current behaviour.
